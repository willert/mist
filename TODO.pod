=head1 BUGS

=over 4

=item

Figure out why Devel::CheckCompiler and friends don't work

=item

From-scratch C<./mpan-install> blocks on STDIN when launched without a
controlling tty whose STDIN reaches EOF (background job, CI, agent harness):
it prints "Restarting ... under perl-X.Y.Z" and then sits at 0% CPU with the
perl process asleep reading fd 0. The perlbrew re-exec passes STDIN straight
through to the relaunched installer and its subprocesses (Mist::Script::perlbrew,
the C<exec> near line 128, and the twin in App::Mist::Context near line 300);
a downstream subprocess reads fd 0 and hangs. Nothing in the install path
legitimately wants STDIN - note the already-commented C<< install-cpanm < /dev/null >>
in perlbrew.pm near line 140, prior evidence of the same hole. Fix: sever STDIN
before the re-exec when there is no tty, e.g. C<< open STDIN, '<', '/dev/null' unless -t STDIN; >>
immediately before the C<exec>. Only takes effect for mpan-install scripts
regenerated by a later C<mist compile>; until then the workaround is to run
C<< ./mpan-install < /dev/null >>.

=back
